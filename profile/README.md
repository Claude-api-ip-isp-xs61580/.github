<p>双 ISP 出口经常被当成一个营销词，买回来才发现两条线其实是同一段地址的两个入口，掉线的时候一起掉。这篇不讲概念，直接给一份决策清单：先判断你的任务能不能承受一次中断，再决定两条线路怎么分工，然后定切换阈值，最后用六项验收确认这套配置真的能用。每一组判断都给了可选项、适用场景和不选它的代价，适合正在评估要不要上双线路、或者已经买了但不确定配得对不对的团队拿去逐条对照。</p>

<h2>一、这份清单怎么用</h2>
<p>清单的价值在于把「要不要买」这种模糊问题，拆成几个能直接回答的是否题。你不需要一次答完全部，按顺序走，任何一条答不上来，就说明这一项还没想清楚，先补这一项。</p>
<p>整份清单分四组判断加一组验收，一共十三个决策点。判断组的结论决定你买什么，验收组的结论决定你能不能上线。两组别混着做，很多人是先验收再回头改需求，改到最后预算超了一倍。</p>

<h2>二、判断一：你的任务承受得起一次中断吗</h2>
<p>这一条决定你要不要双线路，是整份清单里最关键的一问。答案不是「能」或「不能」，而是分三档：可以整批重跑、可以断点续跑、完全不能断。三档对应的配置和预算差出好几倍。</p>
<img src="/tp.png" alt="Claude API 双 ISP 出口主备切换的决策清单与验收要点">
<p>判断标准很具体：如果一个任务中断后，重启的代价是重跑全部请求，且这批请求有计费，那它属于「不可中断」，值得为冗余付钱。如果任务本身有断点记录，重启只补最后几条，那属于「可断点续跑」，冗余的优先级就没那么高，把钱花在出口纯净度上收益更大。</p>
<h3>三档容忍度对应三种配置</h3>
<p>不可中断：主备双线，切换自动化，备用线路常驻预热，每月成本约为单线的 1.6 到 2 倍。可断点续跑：单线加快速重连，配一个低频的备用通道做兜底，成本约为单线的 1.2 倍。可整批重跑：单线即可，把预算放在重跑的时间窗口上。</p>
<h3>别把「怕断」当成「必须双线」</h3>
<p>有些团队的真实痛点不是线路断，而是客户端超时设得太短。把超时从 30 秒调到 90 秒，断连率能降一半，成本是零。先排查这一层，再谈买第二条线。</p>

<h2>三、判断二：两条线路怎么分工</h2>
<p>双 ISP 有三种常见分工，选错会让冗余形同虚设，甚至带来新问题。</p>
<h3>主备模式：一条跑，一条待命</h3>
<p>最稳的一种。所有请求走主线，备用线路只做健康检查，主线路连续失败达到阈值才切。优点是出口稳定，账号的地理轨迹不乱；缺点是备用线路的容量平时闲置。适合长期挂着跑的任务和需要固定出口的场景。切换后建议保持 30 分钟不回切，避免抖动。</p>
<h3>按账号分组：A 组走线一，B 组走线二</h3>
<p>两条线都在用，但每个账号固定在其中一条上，互不交叉。这种模式不是冗余，是扩容——它的价值在于分散，不在于容灾。适合号多、单号负载轻的场景。要接受一个事实：一条线挂了，挂在上面的那组号会一起受影响，除非你再加一层组内备用。</p>
<h3>双活模式：同一账号两条线并发</h3>
<p>不建议用在需要保持登录态的账号上。同一账号在两条出口上并发，出口 IP 不一致，平台侧看到的是同一个会话在两个地方活动，反而容易触发校验。真要提吞吐，应该按账号拆，不该按请求拆。</p>

<h2>四、判断三：切换阈值和预算怎么定</h2>
<p>阈值定得太敏感，线路稍有抖动就切，出口频繁变化；定得太钝，用户已经感知到卡顿了才切。参考做法是按任务类型分档。</p>

<h3>预算重心放在哪</h3>
<p>号少、单号任务重：钱压在出口纯净度和独享性上，带宽够用就行。号多、单号任务轻：钱压在并发数和线路数量上，单条线路的极致纯净度边际收益不高。这个判断能帮你避开一个常见错误——花大价钱买了高带宽，结果出口还是共享段。</p>

<h2>五、上线前的六项验收</h2>
<p>配置完不算完，要验收。六项逐条过，任何一项不过就先别接真实流量。</p>
<h3>前四项：线路本身</h3>
<p>一是两条线路的 ASN 都属于住宅宽带运营商，且城市一致。二是两条线路的出口 IP 不在同一段，避免一起被牵连。三是备用线路做过真实接口调用，不只是 ping 通。四是切换演练至少做过一次，记录下实际切换耗时，超过 30 秒就要优化。</p>
<h3>后两项：业务侧</h3>
<p>五是客户端在切换后能自动恢复会话，不需要人工重新登录。六是日志里能查到每次切换的时间、原因和当时的出口 IP——这条决定了以后出问题能不能复盘。六项都过，这套双线路配置才算真正可用。</p>

<h2>常见问答</h2>
<h3>双 ISP 一定是两条不同运营商的线路吗？</h3>
<p>答：通常指两条归属信息不同的住宅线路，可能是不同运营商，也可能是同运营商的不同地址段。关键看两条线的出口 IP 是否独立、是否同城。如果两条线其实共用同一个出口段，冗余的意义就不大。</p>
<h3>备用线路平时完全不用，会不会切过去不通？</h3>
<p>答：有可能。长时间不用的线路可能已经变更配置或者被回收。所以要定期做主动检查，每周至少跑一次真实接口调用，确认出口 IP 和预期一致。检查结果记进表里，别靠记忆。</p>
<h3>切换之后账号会不会被要求重新验证？</h3>
<p>答：取决于备用出口和主出口的差异。同城、同运营商体系内的切换，通常影响很小；跨城市切换，被要求验证的概率明显上升。所以备用线路选址要跟着主线路走，不要随便找一条便宜的顶上。</p>
<h3>预算有限，只能保一项，保哪个？</h3>
<p>答：保出口纯净度。线路偶尔断可以重试，出口被标记了，重试多少次都没用。纯净度是底线，冗余是加分项，顺序不能颠倒。</p>
